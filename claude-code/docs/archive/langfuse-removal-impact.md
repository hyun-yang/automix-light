# Langfuse 연동 제거 영향 분석

분석일: 2026-10-17. 대상: 현재 로컬 저장소의 코드·명령 문서·테스트. 구현 변경 없이 정적 분석만 수행했다.

## 결론

**Langfuse 외부 전송만 제거하고 로컬 작업 지표 기록은 유지하는 것을 권장한다.** 이 범위라면 핵심 작업 흐름에 대한 위험은 낮고, 명령 인자·테스트·배포 문서의 일관성을 맞추는 작업은 필요하다. Langfuse를 사용하는 사람에게는 웹 대시보드의 신규 데이터 수집이 중단되는 명확한 기능 손실이 있다.

`observe.py` 전체 삭제는 권장하지 않는다. 이 파일은 Langfuse 전송뿐 아니라 모델별 토큰 집계, 예상 비용 계산, 작업 측정 줄 생성, `progress.md` 누적 요약도 담당한다. 전체 삭제 시 영향은 중간 이상으로 커진다.

## 현재 연동 방식

1. `/aml:go`가 작업 종료 후 `observe.py task-done`을 호출한다. 작업 시작 시각, 이름, 기능 제목, 한 줄 검증 결과를 전달한다. 출력 중 `측정: …` 줄은 명령 지침에 따라 `progress.md`에 기록된다. 스크립트가 직접 진행 문서를 쓰는 구조는 아니다. [go.md:31](aml/commands/go.md#L31)
2. 스크립트는 현재 프로젝트에 대응하는 Claude 세션 JSONL에서 해당 시간 구간의 사용량을 합산한다. 로컬 측정 줄을 먼저 출력하고, 그다음 Langfuse 활성화 여부를 확인한다. [observe.py:128](aml/scripts/observe.py#L128), [observe.py:379](aml/scripts/observe.py#L379)
3. `.aml/config.yaml`의 `langfuse` 값이 `on`일 때만 작업 지표 전송을 진행한다. 설정이 없으면 기본값은 꺼짐이다. 인증 정보는 `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` 환경변수에서 읽는다. 호스트 우선순위는 환경변수 → 설정 파일 → 기본 클라우드 주소다. [observe.py:213](aml/scripts/observe.py#L213)
4. Python 표준 라이브러리 `urllib`로 `/api/public/ingestion`에 Basic 인증 POST를 보낸다. Langfuse SDK를 사용하는 구조가 아니다. 네트워크 요청에는 10초 타임아웃을 설정하며, 전송 실패는 경고로 처리한다. [observe.py:288](aml/scripts/observe.py#L288)
5. `/aml:doctor`는 활성화 및 키 존재 여부를 안내하고, 조건이 맞으면 `ping`을 호출한다. 이 `ping`은 읽기 전용 상태 조회가 아니라 시험 trace를 전송한다. `ping` 자체는 활성화 설정을 확인하지 않으므로, 전송을 완전히 없애려면 이 경로도 제거 대상이다. [doctor.md:30](aml/commands/doctor.md#L30), [observe.py:416](aml/scripts/observe.py#L416)
6. `/aml:status`의 누적 요약은 로컬 `progress.md`를 읽으며 Langfuse 조회에 의존하지 않는다. [status.md:21](aml/commands/status.md#L21), [observe.py:325](aml/scripts/observe.py#L325)

## 외부로 보내는 정보

`build_batch()`는 작업 trace, 모델별 generation, 선택적인 검증 event를 생성한다. [observe.py:248](aml/scripts/observe.py#L248)

| 정보 | 현재 전송 내용 | 제거 시 변화 |
|---|---|---|
| 작업 식별 | 작업 이름·번호, 기능 이름 또는 현재 폴더명, trace ID | 신규 작업의 외부 조회·기능별 묶음 중단 |
| 시간 | 시작·종료 시각, 소요 시간 | 외부 시간 분석 중단, 로컬 측정 유지 가능 |
| 사용량 | 모델명, 입력·출력·캐시 토큰 | 외부 사용량 비교 중단, 로컬 집계 유지 가능 |
| 비용 | 알려진 모델의 예상 비용 합계 | 외부 비용 데이터 중단, 로컬 예상 비용 유지 가능 |
| 검증 결과 | `--note`로 받은 자유 형식 한 줄 | 외부 검증 event 및 메모 수집 중단 |

이 전송 코드에는 세션 대화 전문이나 소스 파일 본문을 그대로 실어 보내는 동작이 없다. 다만 작업 이름·기능 제목·검증 메모·폴더명 자체에 내부 정보가 포함될 수 있다. 제거하면 이 경로를 통한 향후 외부 전송이 사라진다. 로컬 세션 파일 읽기와 로컬 측정 기록은 별개다.

## 위험·영향 평가

등급은 현재 코드에 근거한 정성 평가다. 실제 사용자의 Langfuse 의존도는 확인하지 않았다.

| 항목 | 영향·위험 | 평가와 대응 |
|---|---|---|
| 구현·검증의 기본 흐름 | 낮음 | 외부 전송은 기본 꺼짐이고 실패해도 계속하도록 설계됐다. 로컬 측정 경로를 유지하면 Langfuse가 핵심 실행의 필수 의존성은 아니다. |
| 로컬 지표와 `/aml:status` | 전송만 제거하면 낮음, 파일 전체 삭제 시 높음 | `sum_by_model`, `cost_usd`, `measure_line`, `summary`를 보존해야 한다. 파일 전체 삭제 시 지표가 누락되거나 명령 호출이 실패한다. |
| 대시보드 활용 | 사용 중이면 높음, 미사용이면 낮음 | 신규 trace·generation·검증 event가 더 이상 쌓이지 않는다. 외부 보고서나 자동화가 이 데이터에 의존하는지는 별도 확인이 필요하다. |
| CLI 호환성 | 중간 | `go.md`는 현재 `--label`, `--feature`, `--note`를 전달한다. 인자를 먼저 없애면 argparse가 종료 코드 2로 실패해 로컬 측정도 나오지 않는다. 호출부와 파서를 함께 정리하거나 과도기에는 인자를 수용해야 한다. |
| 연결 점검 | 낮음~중간 | `ping`만 삭제하고 doctor 지침을 남기면 존재하지 않는 명령을 호출한다. 점검 항목·도움말을 같이 수정해야 한다. |
| 테스트 회귀 | 중간 | 관측 smoke test가 로컬 측정과 Langfuse 배치 검증을 함께 포함한다. 파일 전체 삭제는 로컬 기능 검증까지 잃게 한다. Langfuse 전용 검증만 정리해야 한다. |
| 외부 통신·지연 | 개선 가능 | 작업 종료 POST와 ping 요청, 인증 키 사용 경로가 사라진다. 요청 지연과 전송 오류가 줄어들 수 있으나 실제 성능 개선량은 측정하지 않았다. |
| 패키지·실행 환경 | 영향 작음 | 전송은 표준 라이브러리 기반이다. SDK 제거에 따른 큰 의존성 감소는 기대할 근거가 없다. 로컬 측정을 유지하면 Python은 계속 필요하다. |
| 기존 데이터·비밀키 | 별도 정리 필요 | 이 연동 코드 제거는 과거 Langfuse 기록 삭제나 키 폐기 작업을 수행하지 않는다. 다른 도구와 키를 공유할 수 있으므로 공용 환경변수·키를 무조건 삭제하면 안 된다. |
| 설치된 구버전 | 중간 | 저장소 변경만으로 이미 설치·복사된 플러그인의 전송이 멈추는 것은 아니다. 실제 사용처의 업데이트가 필요하다. |

특히 README는 상위 도구 `am`의 Langfuse 연동도 같은 환경변수를 사용한다고 설명한다. 따라서 aml 제거 작업에서 공용 키를 폐기하면 다른 도구까지 영향을 받을 수 있다. [aml/README.md:176](aml/README.md#L176)

## 나중에 제거할 경우의 변경 범위

| 파일 | 필요한 정리 |
|---|---|
| `aml/scripts/observe.py` | Langfuse 설정·인증·배치·전송·ping 경로, 전용 상수·import·도움말 정리. 로컬 측정·비용·요약과 공유 함수는 보존. CLI 인자 호환성 결정. |
| `aml/commands/go.md` | 외부 전송 설명과 최종 CLI에 맞지 않는 인자 정리. 측정 줄 기록 지침은 보존. |
| `aml/commands/doctor.md` | Langfuse 상태·키 안내·ping 호출 및 설명 제거. |
| `tests/e2e-smoke-observe.sh` | B 파트의 배치·키·ping 검증 및 C 파트 doctor 연결 검증 조정. 로컬 측정·요약·복사본 실행 검증 보존. |
| `README.md`, `aml/README.md` | 기능 소개, 설정법, 점검 설명, 상위 도구 비교 문구를 실제 지원 범위에 맞게 수정. |
| `aml/references/next-steps.md` | 제거된 연동 안내 링크 정리. |
| `.claude-plugin/marketplace.json`, `aml/.claude-plugin/plugin.json` | Langfuse 지원을 약속하는 배포 설명 수정. |

`aml/commands/status.md`와 `aml/templates/progress.template.md`는 로컬 측정 기능을 그대로 보존한다면 제거 대상이 아니다. 기존 `progress.md` 기록을 변환하거나 삭제할 필요도 없다.

CodeGraph의 `build_batch` 영향 분석은 동일 파일의 `cmd_task_done` → `main` 의존 경로를 확인했다. Markdown 명령 지침과 shell 테스트의 연결은 별도 문자열·내용 조사로 확인했다. Python 호출 그래프만으로 변경 범위를 판단하면 이 연결을 놓칠 수 있다.

## 제거 구현 후 확인해야 할 사항

- 설정 파일이 없어도 작업 종료 시 기존 형식의 측정 줄이 출력된다.
- 기존 설정에 `langfuse: "on"`과 키가 남아 있어도 작업 종료·점검에서 외부 전송을 하지 않는다. 이를 검증할 때 실제 서버 대신 통신 호출을 가로채거나 로컬 시험 서버를 사용한다.
- `/aml:go`에 적힌 명령을 그대로 실행해도 알 수 없는 인자 오류가 발생하지 않는다.
- `/aml:status`가 기존 `progress.md`의 작업 수·시간·토큰·예상 비용을 동일하게 요약한다.
- 세션 기록이나 Python이 없는 경우 기존의 측정 누락 안내와 작업 계속 동작을 유지한다.
- `/aml:doctor`가 삭제된 `ping`이나 키 설정을 안내하지 않는다.
- 관측 smoke test의 로컬 측정·요약·복사본 실행 검증이 통과한다.
- 문서와 플러그인 소개에 삭제된 연동 기능의 사용 안내가 남지 않는다.

## 범위와 한계

실제 Langfuse 서버 접속, 환경변수의 비밀키 열람, 외부 데이터 삭제, 구현 변경, 테스트 실행은 하지 않았다. 따라서 운영 중 활성화 여부, 기존 데이터 양, 대시보드 사용자와 외부 자동화 의존도는 미확인이다. 위 결론은 현재 저장소의 정적 구조에 대한 판단이며 제거 후 동작 검증 결과는 아니다.

사용자 승인으로 분석용 `.codegraph/` 인덱스를 생성했고, 이 분석 문서만 추가했다. `spec.md`, `task.md`, `progress.md`는 작성하지 않았으며 제거 구현도 시작하지 않았다.
