# /aml:review — 커밋 전에 한 번 훑는다

볼 범위: $ARGUMENTS

만든 사람이 자기 코드를 보면 잘 안 보인다. 이 명령은 정해진 기준표(REVIEW.md)를 들고 같은 눈으로 매번 같은 것을 본다.

**이 명령은 코드를 고치지 않는다.** 찾아서 알려 주기만 한다 — 고치는 건 /aml:go 의 몫이고, 무엇을 고칠지 정하는 건 사용자다. 이 명령이 파일에 쓰는 것은 딱 둘뿐이다: REVIEW.md(없을 때 처음 만들기)와 progress.md 의 리뷰 한 줄.

## 1. 기준표 준비

`REVIEW.md` 가 없으면 `${CLAUDE_PLUGIN_ROOT}/templates/review.template.md` 를 그대로 프로젝트 루트에 만들고 한 줄로 알린다: "리뷰 기준표(REVIEW.md)를 만들었습니다 — 마음에 안 드는 기준은 직접 고치셔도 됩니다." 이미 있으면 **절대 덮어쓰지 않는다.**

## 2. 볼 범위 정하기

- 인자가 없으면: 아직 커밋하지 않은 변경 (`git diff`, `git diff --cached`, `git status -s -uall` 로 새 파일까지)
- 인자가 `전체` 면: 프로젝트 코드 전체를 훑는다 (한 달에 한 번쯤 하는 정기 점검. 큰 프로젝트면 spec.md 의 핵심 기능과 관련된 폴더부터)
- 그 밖의 인자는 git 범위로 본다 (`HEAD~3..HEAD` 등)
- 볼 게 없으면(변경 없음) 그렇게 알리고 멈춘다. git 저장소가 아니면 최근에 만든/고친 파일을 사용자에게 물어 정한다.

## 3. 기준 읽기

`REVIEW.md`(무엇을 볼지), `spec.md`(완성 기준 · 정한 것들 · 걱정되는 것), `task.md`(구간별 계획), `CLAUDE.md`, 규칙 카드(`.claude/skills/*/SKILL.md`).

## 4. 세 갈래로 훑기

REVIEW.md 에 적힌 갈래대로 본다. 기본은 셋이다.

1. **버그** — 안 돌아가는 것, 빠뜨린 경우(빈 값, 취소, 두 번 누르기, 인터넷 끊김, 아주 긴 입력)
2. **안전** — 코드에 박힌 비밀번호·API 키, 화면이나 기록에 새는 남의 정보, 사용자가 넣은 값을 그대로 믿는 곳
3. **약속 지킴** — spec.md 의 완성 기준·정한 것들과 다른 곳, task.md 의 계획과 달라졌는데 계획서를 안 고친 곳, "걱정되는 것"에 적어 둔 위험이 실제로 처리됐는지

지적 하나는 이렇게 적는다:

```
[중요·버그] todo.html:42 — 제목을 비워 두고 저장하면 화면이 하얗게 됩니다.
   왜: 빈 값을 거르는 곳이 없어서 그다음 줄에서 멈춥니다.
   어떻게: 저장하기 전에 제목이 비었는지 확인하고, 비었으면 안내 문구를 보여 주세요.
```

- **중요**: 동작이 깨지거나 · 정보가 새거나 · spec.md 에서 정한 것을 어긴 것
- **사소**: 그 외 전부. **5개까지만** 적고 나머지는 "그 외 N개"로 숫자만 남긴다.
- REVIEW.md 의 "보지 않을 것"에 해당하는 건 아예 보지 않는다.
- 확실하지 않으면 "확인 필요"로 적고 어떻게 확인하는지 알려 준다. 추측을 중요로 올리지 않는다.

## 5. 되풀이되는 지적 찾기

progress.md 의 지난 리뷰 줄을 훑어, 이번 지적 중 **두 번째로 나온 유형**이 있으면 표시한다. 있으면 이렇게 권한다: "같은 지적이 두 번째입니다 — `/aml:rule` 로 규칙을 만들어 두면 다음부터는 이 실수가 안 나옵니다."

## 6. 기록과 마무리

progress.md 의 가장 최근 기록에 한 줄을 더한다:

`- 리뷰: 중요 2 · 사소 4 (되풀이: 커밋 전에 테스트를 안 돌림)`

그리고 마무리 안내:

- 중요한 게 있으면: "중요한 것 N개를 먼저 고치는 게 좋겠습니다. `/aml:go` 로 고친 뒤 다시 `/aml:review` 를 돌려 보세요."
- 없으면: "지금 커밋해도 괜찮습니다." (다 만든 상태라면 `/aml:next` 도 함께 권한다)
