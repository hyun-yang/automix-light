# /aml:go — 구현

프로젝트 루트의 spec.md, task.md, progress.md(최신 기록), CLAUDE.md 를 읽는다. intent.md 와 규칙 카드(`.claude/skills/*/SKILL.md`)가 있으면 그것도 읽는다. spec.md 나 task.md 가 없으면 /aml:new 부터 하라고 알리고 멈춘다. 상태가 이상해 보이면 /aml:doctor 로 점검할 수 있다고 알린다.

시작 전에 `.aml/FIXING` 이 남아 있는지 본다. 있으면 지난번에 버그를 고치다 중간에 멈춘 흔적이니, 사용자에게 한 줄로 알리고 지운 뒤 진행한다.

지금 함께 일하는 사람은 초보자다. 보고와 기록은 모두 **한국어**로, 프로그래밍을 모르는 사람이 알아듣는 말로 쓴다.

## 할 일 반복

task.md 의 체크되지 않은 할 일을 순서대로:

1. **계획 확인** — 그 할 일이 속한 구간의 `바뀌는 파일 / 위험 / 증명` 을 먼저 본다.
   - 위험이 "낮음"이고 증명할 방법(테스트나 눈으로 볼 화면)이 있으면, 한 줄로 알린다: "이 할 일은 맡겨 두셔도 됩니다 — 중간에 하나씩 확인하지 않고 끝까지 만든 뒤 결과를 보여 드립니다."
   - 위험이 적혀 있으면 그 부분은 한 걸음씩 진행하고, 손대기 전에 무엇을 할지 먼저 말한다.

2. **구현** — 시작할 때 `date -Is`(또는 ISO8601 시각을 만드는 다른 방법)로 시작 시각을 기록해 둔다. spec.md 의 "정한 것들"과 참고 자료(목업·화면 캡처), 규칙 카드를 지도 삼아 구현한다.
   - **버그를 고치는 일이면 실패하는 테스트를 먼저 쓴다.** 문제를 그대로 재현하는 테스트를 쓰고, 실제로 실패하는지 확인하고, `.aml/FIXING` 파일을 만든 다음(`mkdir -p .aml && touch .aml/FIXING`) **코드만** 고쳐서 통과시킨다. 통과하면 `rm .aml/FIXING`. 고치는 동안 테스트 파일을 수정하려 하면 안전망이 막는다 — 그건 버그가 사라진 게 아니라 확인이 사라지는 것이기 때문이다.
   - **화면이 있는 일이면 눈으로 맞춰 본다.** 만들고 → 실행하거나 스크린샷을 찍고 → spec.md 의 참고 자료(고른 목업)와 비교하고 → 다듬는다. 두세 번 돌면 대개 비슷해진다.
   - **계획과 달라지면 그 자리에서 task.md 를 고친다.** 바뀐 파일·위험·증명 줄을 지금 상태에 맞게 수정하고, 왜 달라졌는지 한마디 붙인다. 계획서와 실제가 다른 채로 두지 않는다.

3. **검증** — CLAUDE.md 의 "확인하는 법"에 적힌 명령을 그대로 돌리고 그 출력을 그대로 보여 준다. 테스트가 없으면 실제로 실행해 동작을 확인한다. 이 할 일과 관련된 spec.md 의 "완성 기준" 항목과 맞춰 본다. **테스트가 실패하면 테스트가 아니라 코드를 고친다.**

4. **기록** — task.md 에서 해당 할 일을 체크하고, progress.md 맨 위에 기록을 하나 추가한다: 한 일 / 확인 결과 / **메모**(계획과 다르게 한 것과 그 이유 — 초보자는 코드 대신 이 기록을 읽는다) / **측정 줄** / 다음. 측정 줄은 한 번의 호출로 얻는다:

   `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/observe.py" task-done --since <시작 시각> --label "<할 일 번호와 이름>" --feature "<spec.md 제목>" --note "<한 줄 검증 결과>"`

   출력된 "측정: …" 줄을 그대로 붙여 넣는다 — 이 줄은 스크립트가 만든 형식 그대로 두고 손대지 않는다 (Langfuse 를 켜 두었다면 같은 호출이 전송까지 한다 — 전송 실패는 무시하고 계속한다). 호출 자체가 실패하면(python3 없음 등) `측정: 기록 없음` 이라고 적고 계속한다.

5. **커밋** — git 저장소면 할 일 하나가 끝날 때마다 커밋한다(예: `feat: 1.2 카드 추가 창`). 되돌리고 싶을 때 이 단위로 되돌릴 수 있다. git 저장소가 아니면 조용히 건너뛴다.

같은 문제가 3번 시도해도 풀리지 않으면 멈춘다: 막힌 지점을 progress.md 에 남기고, 상황을 쉬운 말로 설명한 뒤 사용자에게 묻는다.

## 다 끝났을 때

1. **독립 확인** — `Task` 도구로 `aml:verifier` 서브에이전트를 부른다. 새 맥락에서 직접 실행해 보는 확인이라, 만든 사람의 착각이 섞이지 않는다. 넘겨줄 것: spec.md 의 "완성 기준" 목록(그대로), CLAUDE.md 의 "확인하는 법" 명령, 이번에 무엇을 만들었는지 한 줄. 돌아온 결과에서 "안 됨"이 있으면 고치고 다시 부른다(최대 2번).
2. **완성 기준 확인** — spec.md 의 "완성 기준" 항목을 하나씩 실제로 확인하고 체크한다. 안 되는 게 있으면 고치고 다시 확인한다.
3. **리뷰** — REVIEW.md 를 읽고 `/aml:review` 와 같은 절차로 지금 한 번 훑는다(버그 · 안전 · 약속 지킴). 중요한 지적이 나오면 고치고 2번부터 다시. 결과 한 줄을 progress.md 에 남긴다.
4. **마무리 커밋** — git 저장소면 커밋한다.
5. **마무리 보고** — 무엇이 만들어졌는지, 직접 확인하는 방법(실행하는 법), 그리고 다음 안내: "직접 써 보시고 `/aml:next` 를 실행하면, 써 보면서 느낀 걸 다음 할 일로 옮겨 드립니다." 이해했는지 확인하고 싶으면 /aml:status 의 퀴즈를 권한다.
