# automix-light (aml) — 한국어판

> automix 의 가벼운 버전. 초보자가 원하는 건 하나다 — **빠르고 정확한 구현**.

automix(am)는 기획 검증, 코드 리뷰, 팀 모드, 패턴 라이브러리, 외부 관측까지 갖춘 완전한 작업 틀이다. 첫 앱을 만드는 사람에게는 대부분 아직 필요 없다. automix-light 는 초보자에게 실제로 필요한 것만 남겼다.

v0.6.0 은 Anthropic 의 [AI-Native SDLC 플레이북](https://claude.com/blog/the-ai-native-sdlc-playbook)을 **혼자 만드는 사람 크기로** 옮긴 판이다. 플레이북의 뼈대는 한 문장이다 — *단계마다 파일 하나를 남기고, 다음 단계는 그 파일을 읽고 시작한다.* aml 은 그 사슬을 초보자가 읽을 수 있는 한국어 파일로 만든다.

```
intent.md  →  spec.md  →  task.md  →  코드 + progress.md  →  리뷰  →  다음 intent.md
왜 만드나    무엇 + 완성기준  계획(파일·위험·증명)   한 일 + 측정      약속 지켰나    한 바퀴 더
```

- **명령 7개** — `/aml:new` → `/aml:go` → `/aml:review` → `/aml:next`, 그리고 `/aml:rule`(규칙 굳히기) · `/aml:status`(진행 확인) · `/aml:doctor`(점검).
- **md 우선** — 명령·템플릿·산출물이 모두 마크다운, 모두 한국어. 예외는 관측 스크립트 하나(`scripts/observe.py`, 파이썬 표준 라이브러리만)와 안전망 훅 하나(`hooks/aml-guard.sh`).
- **안전망** — 되돌리기 어려운 일 세 가지를 막는다. 막을 때는 이유와 해결 방법을 함께 말한다.
- **독립 확인** — 다 만들었다고 하면 `verifier` 도우미가 **새 눈으로 직접 실행해** 확인한다. 만든 사람의 착각이 섞이지 않는다.

설계의 뿌리는 "A Field Guide to Fable" 이다: 작은 프롬프트, 제약보다 맥락, 그리고 **시작하기 전에 모르는 것부터 캐낸다**. 초보자는 자기가 무엇을 모르는지조차 모르는 상태(Unknown Unknowns)에서 출발한다 — 그래서 첫 명령이 구현이 아니라 인터뷰다.

## 설치

```bash
cd automix-light
./install.sh          # ~/.claude-marketplaces/automix-light 로 복사됩니다
```

그다음 Claude Code 안에서:

```
/plugin marketplace add ~/.claude-marketplaces/automix-light
/plugin install aml@automix-light
```

`/help` 에 `/aml:new` 부터 `/aml:doctor` 까지 보이면 설치가 끝난 것이다.

## 흐름

### 1. `/aml:new "한 줄: 무엇을 만들고 싶은지"`

먼저 준비물부터 갖춘다. `CLAUDE.md`(Claude Code 가 매 세션 자동으로 읽는 안내 파일)와 `REVIEW.md`(리뷰 기준표)가 없으면 만들어 주고 — **이미 있으면 손대지 않는다** — git 저장소가 아니면 초기화한 뒤 기본 브랜치를 `main` 으로 맞춘다.

그다음 **`intent.md`** 를 쓴다. 인터뷰로 다듬기 전에, 사용자가 한 말 그대로 "왜 만들고 싶은지"를 남기는 파일이다. 나중에 길을 잃으면 여기로 돌아온다.

그리고 인터뷰로 지도를 그린다. 네 구역을 차례로 캐낸다.

| 구역 | 뜻 | 끌어내는 방법 |
|---|---|---|
| KK (아는 것을 아는) | 이미 말한 것 | 그대로 적는다 |
| UU (모르는 줄도 모르는) | 생각해 보지 못한 정할 거리 | "보통 이런 걸 정합니다" 목록을 먼저 보여 준다 |
| KU (모르는 걸 아는) | 아직 안 정한 것 | 선택지가 있는 질문, "추천해 주세요" 가능 |
| UK (말로는 못 하지만 아는) | 설명은 못 해도 보면 안다 | 느낌이 다른 목업 3~4개 중에서 고른다 |

결과로 `spec.md`(완성 기준 + **걱정되는 것**)와 `task.md`(구간마다 **바뀌는 파일 / 위험 / 증명**)가 만들어지고, 사용자가 검토한다.

### 2. `/aml:go`

`task.md` 를 순서대로 구현한다. 할 일마다:

1. **계획 확인** — 위험이 "낮음"이고 증명할 방법이 있으면 "맡겨 두셔도 됩니다"라고 알린다.
2. **구현** — 버그를 고치는 일이면 **실패하는 테스트를 먼저** 쓴다. 화면이 있으면 목업과 두세 번 맞춰 본다. 계획과 달라지면 그 자리에서 task.md 를 고친다.
3. **검증** — CLAUDE.md 의 "확인하는 법"에 적힌 명령을 그대로 돌리고 출력을 보여 준다.
4. **기록** — `progress.md` 맨 위에 한 일 / 확인 / 메모 / **측정 줄** / 다음.
5. **커밋** — 할 일 하나가 끝날 때마다.

다 끝나면 `verifier` 도우미의 독립 확인 → 완성 기준 체크 → 리뷰 → 마무리 커밋 순으로 마감한다.

**측정 줄**은 할 일마다 한 줄씩 남는다:

```
- 측정: claude-opus-4-8 · 4분 32초 · 토큰 입력 12.3k / 출력 4.1k (캐시 읽기 88k / 쓰기 2.1k) · 예상 비용 $0.42
```

읽는 법: 어떤 모델이 · 얼마나 걸려서 · 토큰(대화량)을 얼마나 써서 그 할 일을 끝냈고, 비용은 대략 얼마였는지. 공개 가격표로 계산한 추정치라 실제 청구액과 다를 수 있다. python3 이 없으면 `측정: 기록 없음` 으로 남지만 구현은 그대로 진행된다.

### 3. `/aml:review`

커밋하기 전에 `REVIEW.md` 기준으로 세 갈래를 훑는다 — **버그** · **안전**(비밀키·남의 정보) · **약속 지킴**(spec.md·task.md 대로인가). 중요한 것과 사소한 것을 나누고, 사소한 건 5개까지만 적는다. **코드는 고치지 않는다** — 찾아서 알려 주기만 하고, 고치는 건 `/aml:go` 가 한다.

`/aml:review 전체` 로 코드 전체를 훑는 정기 점검도 할 수 있다.

### 4. `/aml:next`

만들고 끝내면 반쪽이다. 직접 써 보고 나온 것을 다음 바퀴로 잇는다 — 작은 문제는 `task.md` 에 할 일로, 큰 것은 `intent.md` 에 새 의도로. 고친 버그는 `spec.md` 의 완성 기준에 한 줄로 영구히 남아, 다음에 뭔가 만들 때 그게 다시 깨졌는지 자동으로 확인된다.

### 5. `/aml:rule`

같은 실수가 **두 번** 나오면 규칙으로 굳힌다. 짧은 습관은 `CLAUDE.md` 한 줄로, 순서가 있는 절차는 규칙 카드(`.claude/skills/<이름>/SKILL.md`)로. 규칙 카드는 다음 세션부터 Claude 가 알아서 꺼내 쓴다.

### 6. `/aml:status`

어디까지 왔는지, 막힌 건 없는지, 지표(완성 기준 통과율 · 되풀이 지적 · 누적 시간과 비용)를 쉬운 말로 보여 준다. 원하면 **퀴즈** — 만든 걸 다른 사람에게 설명할 수 있는지 확인한다.

### 7. `/aml:doctor`

시작 전에(또는 뭔가 이상할 때) 상태를 점검한다. 읽기 전용이라 아무것도 고치지 않는다.

- ❌ **막는 항목**: spec.md/task.md/progress.md 없음, 완성 기준이나 할 일 체크박스 없음 → `/aml:new` 안내
- ⚠️ **참고만**: CLAUDE.md·intent.md·REVIEW.md 없음, 고치는 중 표시(`.aml/FIXING`) 잔류, 안전망 상태, git·python3 없음, 설정을 바꾼 뒤 확인 안 함, Langfuse 설정

## 안전망 (자동, 끌 수 있음)

`spec.md` 와 `task.md` 가 있는 폴더에서만 동작한다. 다른 저장소에는 아무 영향이 없다.

| 막는 것 | 왜 |
|---|---|
| `.env` 를 저장소에 넣기 | 비밀번호·API 키는 한 번 들어가면 지워도 기록에 남는다 |
| 버그 고치는 중 테스트 파일 수정 | 테스트를 고치면 버그가 아니라 "확인"이 사라진다 |
| 강제 푸시 · 하드 리셋 · 통째로 지우기 | 되돌릴 수 없다 |

끄려면 `.aml/config.yaml` 에 `guard: "off"`. 자세한 이야기와 직접 안전망을 추가하는 법은 `references/autonomy-and-guardrails.md`.

## Langfuse 켜기 (선택, 기본 꺼짐)

[Langfuse](https://langfuse.com) 는 LLM 작업을 대시보드로 보여 주는 관측 도구다. 켜 두면 할 일마다 측정 데이터(모델·토큰·시간·검증 결과)가 전송되어, 기능별로 묶인 흐름을 웹에서 볼 수 있다. **꺼 두어도 아무 차이 없다** — progress.md 기록은 언제나 남는다.

1. Langfuse 프로젝트(클라우드 또는 자체 호스팅)에서 public/secret 키를 받는다.
2. 키는 **환경변수로만** 설정한다 (설정 파일에는 넣지 않는다):
   ```bash
   export LANGFUSE_PUBLIC_KEY=pk-...
   export LANGFUSE_SECRET_KEY=sk-...
   export LANGFUSE_HOST=https://cloud.langfuse.com   # 자체 호스팅이면 그 주소
   ```
3. 프로젝트 루트에 `.aml/config.yaml` 을 만든다:
   ```yaml
   langfuse: "on"        # "off" 이거나 파일이 없으면 전송 안 함 (기본값)
   langfuse_host: ""     # 비우면 LANGFUSE_HOST, 그것도 없으면 cloud.langfuse.com
   guard: "on"           # 안전망 (기본 켜짐, "off" 로 끕니다)
   ```
4. `/aml:doctor` 로 연결을 확인한다 — "정상: Langfuse 연결을 확인했습니다" 가 보이면 끝.

전송은 최선 노력이다: 네트워크가 끊기거나 키가 틀리면 경고 한 줄만 남기고 구현은 계속된다.

## 예시 한 판

```
/aml:new "칸반처럼 쓰는 할 일 앱, HTML 파일 하나로"
  → git 준비(기본 브랜치 main) + CLAUDE.md + REVIEW.md 생성
  → intent.md: "포스트잇으로 하던 걸 노트북에서 하고 싶다"
  → "보통 이런 걸 정합니다: 칸 개수, 마감일, 끝낸 카드는 어디로, 끌어서 옮기기…"
  → 질문 5개(선택지 포함) → 목업 4개 → 3번 선택
  → spec.md + task.md + progress.md 생성, 검토 요청

/aml:go
  → 1.1 보드 화면 → 검증 → 기록(측정: claude-opus-4-8 · 3분 11초 · …) → 커밋
  → 1.2 카드 추가 창 → …
  → verifier 독립 확인 → "완성 기준 7개 전부 됨" → 리뷰 → 마무리 커밋

/aml:review
  → [중요·안전] 없음 / [사소] 2개 → "지금 커밋해도 괜찮습니다"

/aml:next
  → "써 보니 카드가 많아지면 느려요" → task.md 에 할 일 추가
  → "달력 보기도 있으면" → intent.md 에 새 의도 → /aml:new
```

## 언제 automix(am)로 넘어가나

앱을 **꾸준히** 만들게 될 때다 — 독립 검증 관문(goal), 팀 실행, 프로젝트를 넘나드는 패턴 라이브러리, 예산 상한, 되돌리기 명령이 필요해지면 am 에 전부 있다. 기획 → 할 일 → 검증이라는 뼈대는 같아서, aml 에서 익힌 흐름이 그대로 이어진다. am 의 Langfuse 연동(`/am:observe`)도 같은 환경변수를 쓴다.
