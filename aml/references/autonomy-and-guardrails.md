# 작업 위임과 위험한 작업 차단

Claude에게 맡길 작업 범위를 정할 때는 변경의 위험, 복구 가능성, 검증 방법을 함께 고려합니다.

## 자동 진행에 적합한 조건

다음 네 가지 조건을 모두 충족하면 작업 중간의 확인을 줄이고, 완료 후 결과를 검토하는 방식으로 진행할 수 있습니다.

1. **위험이 낮습니다.** `task.md`에서 해당 작업 구간의 “위험”이 “낮음”으로 표시되어 있습니다.
2. **변경을 되돌릴 수 있습니다.** Git 저장소이며, 작업 시작 전 상태가 커밋되어 있습니다.
3. **결과를 검증할 수 있습니다.** 테스트나 화면 확인 등 검증 방법이 `task.md`의 “증명” 항목에 정리되어 있습니다.
4. **작업 차단 기능이 활성화되어 있습니다.** `/aml:doctor`에서 “안전망 켜짐”을 확인했습니다.

조건을 충족하지 못하면 작업을 나누어 단계별로 확인합니다. 결제, 메일 발송, 서버 배포처럼 외부에 영향을 주거나 되돌리기 어려운 작업은 실행 전에 사용자가 확인합니다.

작업을 맡기려면 `/aml:go`에 “이 구간은 끝까지 진행해 주세요”라고 요청할 수 있습니다. Claude Code 입력창에서 `Shift+Tab`으로 편집 승인 모드를 변경하는 방법도 있습니다. 자동 진행을 선택했더라도 완료 후에는 변경 내용과 검증 결과를 검토합니다.

## aml이 차단하는 작업

작업 차단 훅은 `spec.md`와 `task.md`가 있는 폴더에서 동작합니다.

| 차단하는 작업 | 이유 | 필요한 조치 |
|---|---|---|
| `.env` 파일 커밋 | 비밀번호와 API 키는 파일을 삭제해도 Git 기록에 남을 수 있습니다. | `.gitignore`에 `.env`를 추가하고, 민감한 값은 Git에서 제외된 로컬 파일로 관리합니다. |
| 버그 수정 중 테스트 파일 변경 | 테스트를 바꿔 오류를 통과시키면 실제 버그가 해결되지 않을 수 있습니다. | 테스트 자체가 잘못된 경우에만 수정 필요성을 확인한 뒤 `rm .aml/FIXING`으로 차단 상태를 해제합니다. |
| 강제 푸시, 하드 리셋, 대량 파일 삭제 | 작업 내용이나 기록이 사라져 복구하기 어려울 수 있습니다. | 작업의 영향 범위를 확인한 뒤 사용자가 직접 터미널에서 실행합니다. |

작업이 차단되면 이유와 필요한 조치를 함께 안내합니다.

비활성화하려면 `.aml/config.yaml`에 다음을 설정합니다.

```yaml
guard: "off"
```

민감한 정보 노출이나 작업 내용 손실을 예방하려면 기본 설정인 활성화 상태를 유지하는 것을 권장합니다.

## 개발 규칙과 작업 차단 훅의 차이

- **규칙 카드**(`.claude/skills/`)는 Claude가 작업할 때 참고하는 지침입니다. 상황에 따른 판단이나 여러 단계의 절차를 설명할 때 사용합니다.
- **작업 차단 훅**은 도구 실행 전에 정해진 조건을 검사하는 스크립트입니다. 조건에 맞는 작업을 자동으로 차단할 때 사용합니다.

중요한 규칙은 지침으로 설명하고, 자동으로 판별할 수 있는 위반 사항은 훅으로도 검사할 수 있습니다. 훅의 차단 범위는 스크립트에 작성된 검사 조건에 따라 달라집니다.

## 프로젝트별 차단 규칙 추가

`.claude/settings.json`에 훅을 등록하고, 스크립트가 작업을 차단해야 할 때 종료 코드 `2`를 반환하도록 작성합니다.

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command",
            "command": "bash ${CLAUDE_PROJECT_DIR}/.claude/hooks/my-guard.sh" }
        ]
      }
    ]
  }
}
```

다음은 명령에 `deploy --prod`가 포함되어 있으면 차단하는 예시입니다.

```bash
#!/usr/bin/env bash
# .claude/hooks/my-guard.sh — 운영 서버 배포 명령은 사용자가 직접 실행하도록 안내
CMD=$(cat | python3 -c 'import json,sys; print(json.load(sys.stdin).get("tool_input",{}).get("command",""))' 2>/dev/null)
if echo "$CMD" | grep -q "deploy --prod"; then
  echo "운영 서버에 배포할 내용을 확인한 뒤 직접 실행해 주세요." >&2
  exit 2      # 작업 차단. 이 메시지는 Claude에게 전달됩니다.
fi
exit 0
```

이 예시에서 **종료 코드 `0`은 통과, `2`는 차단**을 뜻합니다. 차단 메시지에는 이유와 다음 조치를 함께 적습니다. 예시는 입력 처리에 실패하면 작업을 통과시키는 방식입니다. 오류가 발생했을 때 통과시킬지 차단할지는 프로젝트의 요구사항에 맞춰 정해야 합니다.

자세한 설정은 공식 문서의 [훅 안내](https://code.claude.com/docs/en/hooks-guide)와 [설정](https://code.claude.com/docs/en/settings)을 참고하세요.
