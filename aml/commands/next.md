# /aml:next — 한 바퀴 더

만들고 끝내면 반쪽이다. 진짜 쓸 만해지는 건 **써 보고 고친 다음**이다. 이 명령은 사용자가 써 보면서 느낀 것을 다음 할 일로 옮긴다.

프로젝트 루트의 intent.md(있으면), spec.md, task.md, progress.md 를 읽는다. spec.md 가 없으면 /aml:new 부터 하라고 알리고 멈춘다.

## 1. 지금까지를 한 줄로

완성 기준 몇 개 중 몇 개가 확인됐는지, 마지막으로 무엇을 했는지 쉬운 말로 한두 줄 요약한다.

## 2. 써 본 이야기를 듣는다

한 번에 하나씩 묻는다. 초보자가 답하기 쉽게 예를 곁들인다.

1. **잘 되던가요?** — 생각한 대로 움직인 것
2. **안 되거나 이상했던 것은요?** — 눌렀는데 아무 일도 안 일어남, 느림, 헷갈림, 글자가 잘림… 무엇이든
3. **있었으면 하는 것은요?** — 쓰다 보니 아쉬웠던 것

"딱히 없어요"도 답이다. 그러면 3번만 조금 더 파 본다.

## 3. 나온 것을 나눈다

| 이런 것이면 | 이렇게 |
|---|---|
| 지금 고칠 수 있는 작은 문제 | `task.md` 에 새 할 일로 추가한다. 새 구간을 만들고 **바뀌는 파일 / 위험 / 증명** 세 줄도 채운다 → 끝나면 `/aml:go` 안내 |
| 새 기능이거나 방향이 바뀌는 큰 것 | `intent.md` 맨 위에 오늘 날짜로 새 의도를 쓴다(사용자 말 그대로, 템플릿의 칸을 채워서) → `/aml:new` 안내 |
| 지금은 안 할 것 | intent.md 의 "이번에 하지 않을 것"이나 progress.md 에 이유와 함께 한 줄로 남긴다 |

무엇이 어디로 갔는지 마지막에 한 번에 보여 준다.

## 4. 고친 문제는 확인 목록에 영구히 남긴다

이번 바퀴에서 **고친 버그**가 있으면 `spec.md` 의 "완성 기준"에 한 줄로 추가한다(날짜와 함께):

`- [x] 제목을 비워 두고 저장해도 앱이 멈추지 않는다 (2026-09-10 고침)`

앞으로 /aml:go 는 끝날 때마다 이 목록을 전부 다시 확인한다. 한 번 고친 문제가 다음에 만든 것 때문에 다시 깨지면 그때 잡힌다 — 이 목록이 길어질수록 안전해진다.

## 5. 가끔은 전체를 한 번 본다

마지막 전체 점검이 한 달쯤 전이거나 처음이면 권한다: "`/aml:review 전체` 로 지금 코드 전체를 한 번 훑어볼까요? 새로 만든 것 말고, 예전에 만든 것에서 위험한 게 없는지 봅니다."

더 큰 안전망(정기 자동 점검, 여러 사람이 함께 쓰기)이 필요해지면 `${CLAUDE_PLUGIN_ROOT}/references/next-steps.md` 를 안내한다.

## 6. 마무리

git 저장소면 바뀐 파일들을 커밋한다(`next: <한 줄>`). 그리고 다음에 뭘 하면 되는지 한 줄로 알려 준다 — 할 일이 생겼으면 `/aml:go`, 새 의도를 썼으면 `/aml:new`.
