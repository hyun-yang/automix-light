# aml-rule — 같은 실수를 세 번째로 하지 않게

규칙으로 만들 것: 사용자가 말한 규칙 (말하지 않았으면 기록에서 찾아 제안한다)

사람이 기억해서 막는 실수는 언젠가 다시 난다. 파일에 적어 두면 Codex 가 다음 세션부터 알아서 지킨다. 이 스킬은 **두 번 일어난 일**을 규칙으로 굳힌다 — 한 번 있었던 일은 아직 규칙이 아니다.

## 1. 무엇을 규칙으로 만들지 정한다

- 사용자가 규칙을 말했으면 그것으로 시작한다.
- 없으면 `progress.md` 를 훑어 **두 번 이상** 나온 것을 찾는다: 메모("계획과 다르게 한 것"), 리뷰 줄의 지적, 막힘 기록. 최대 3개를 근거(언제 있었는지)와 함께 보여 주고 고르게 한다.
- 두 번 이상 나온 게 없으면 그대로 알리고 멈춘다: "아직 규칙으로 만들 만큼 반복된 것이 없습니다. 한 번 있었던 일은 그냥 그때의 실수일 수 있습니다."

## 2. 어디에 넣을지 정한다

| 이런 것이면 | 여기에 |
|---|---|
| 짧은 한 줄이고, 이 프로젝트에서만 통하는 습관 | `AGENTS.md` |
| 순서가 있는 절차(3단계 이상)거나 다른 프로젝트에서도 쓸 것 | 규칙 카드 `.agents/skills/<이름>/SKILL.md` |
| 일어나면 되돌릴 수 없는 것(지우면 끝, 돈이 나감, 정보가 샘) | 말로 하는 규칙만으로는 부족하다 — 아래 참고 |

**되돌릴 수 없는 것**이라면 솔직하게 알린다: "이 버전에는 AML 전용 차단 훅이 없습니다. Codex 의 권한·샌드박스·승인 설정은 환경에 따라 적용되며, Claude 판 AML 훅과 같은 차단을 보장하지 않습니다." 그래서 규칙 카드에 "이 일은 하기 전에 반드시 사용자에게 묻는다"를 넣고, 사용자가 직접 Codex 의 승인 설정을 살펴보도록 권한다. 사용자 설정 파일(`~/.codex/config.toml` 등)은 묻기 전에 바꾸지 않는다. 규칙 카드는 "대개 지켜지게" 만들 뿐 "아예 못 하게" 만들지는 못한다.

**Claude Code 에서 쓰던 규칙 카드**(`.claude/skills/`)가 있으면 자동으로 옮기지 않는다. 계속 지킬 규칙인지 사용자에게 물어보고, 지킬 것만 이 스킬로 `.agents/skills/` 에 새로 적는다. 원래 카드는 지우거나 고치지 않는다.

## 3. 쓴다

- **AGENTS.md** — "Codex 가 자꾸 틀리는 것"(실수를 막는 것) 또는 "지켜 주세요"(항상 지킬 것)에 한 줄 추가한다. AGENTS.md 는 매 세션 전부 읽히니 **한 페이지를 넘기면 안 된다** — 넘칠 것 같으면 이제 안 맞는 오래된 줄을 지울지 먼저 묻는다. AGENTS.md 가 없으면 [AGENTS 템플릿](../../templates/agents.template.md) 으로 먼저 만든다.
- **규칙 카드** — [규칙 카드 템플릿](../../templates/skill.template.md) 을 따라 `.agents/skills/<영문-이름>/SKILL.md` 를 만든다. 본문보다 `description` 이 중요하다: **언제 이 카드를 꺼내야 하는지**를 구체적으로 쓴다("API 를 새로 만들거나 고칠 때 사용"처럼). 이 한 문장만 보고 꺼낼지 정하기 때문이다. 같은 이름의 카드가 이미 있으면 덮어쓰지 않고 다른 이름을 쓰거나 사용자에게 묻는다.

## 4. 진짜 불려 오는지 확인한다

규칙 카드는 새 세션에서 읽힌다. 그 규칙이 필요한 상황을 **서로 다른 말로 두 번** 적어 사용자에게 건네고, 새 Codex 세션에서 물어봐서 카드가 꺼내지는지 확인해 달라고 안내한다. 지금 세션에서 직접 확인하지 못했으면 "불려 오는지: 아직 확인 못 함"이라고 적는다. 안 꺼내지면 `description` 이 좁은 것이니 상황을 더 넓게 다시 쓴다.

## 5. 기록한다

progress.md 최신 기록에 한 줄 더한다:

`- 규칙 추가: 커밋 전에 테스트 돌리기 (이유: 같은 지적 2번) → AGENTS.md`

git 저장소면 커밋한다(`rule: <한 줄>`). 규칙이 언제 왜 생겼는지가 기록으로 남는다.
