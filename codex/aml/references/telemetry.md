# 측정 — Codex 판 측정 줄은 어떻게 만들어지나

$aml:go 는 할 일마다 `progress.md` 에 측정 줄을 하나 남깁니다. 숫자는 `scripts/observe.py` 가 Codex 의 세션 기록을 읽어 만듭니다. 측정은 **작업을 막지 않습니다** — 어떤 이유로든 확실하지 않으면 숫자를 지어내지 않고 `측정: 기록 없음 (이유)` 를 남깁니다.

```text
측정: gpt-6-astra · 4분 12초 · 토큰 입력 12.3k / 출력 2.1k (캐시 읽기 85.0k) · 비용 미산정
```

## 부르는 법

```bash
python3 "<패키지>/scripts/observe.py" task-start --label "1.2 카드 추가 창"
#  → 시작: 2026-10-17T06:00:00+10:00      (이 시각을 아래 --since 에 씀)
python3 "<패키지>/scripts/observe.py" task-done --since 2026-10-17T06:00:00+10:00 --label "1.2 카드 추가 창"
python3 "<패키지>/scripts/observe.py" summary progress.md     # $aml:status
python3 "<패키지>/scripts/observe.py" check                   # $aml:doctor
```

## 어느 세션을 읽나

- Codex 가 명령을 실행할 때 넘겨주는 세션 번호(`CODEX_THREAD_ID`, 없으면 `CODEX_SESSION_ID`)로 **지금 세션 하나만** 고릅니다. `--session <번호>` 로 직접 줄 수도 있습니다.
- 기록 파일은 `$CODEX_HOME/sessions/`(기본 `~/.codex/sessions/`) 아래 `rollout-*-<세션 번호>.jsonl` 입니다. 파일 안 `session_meta` 의 번호가 같아야 읽습니다.
- 세션 번호를 모르면 **같은 폴더(cwd)에서 연 다른 세션을 대신 고르지 않습니다.** 같은 프로젝트에서 연 다른 작업이 섞이기 때문입니다. 이때는 `기록 없음` 입니다.

## 구간은 어떻게 자르나

- 기록 파일의 `token_count` 이벤트에는 세션이 시작된 뒤 지금까지의 **누적** 사용량(`total_token_usage`)이 들어 있습니다.
- 구간 사용량 = (끝까지의 누적값) − (시작 시각 직전의 누적값). 시작 시각 뒤, 지금 이전의 이벤트만 셉니다.
- 시작 시각 직전 이벤트가 없으면 `task-start` 가 `.aml/codex-measure-start.json` 에 저장해 둔 시작값을 씁니다(같은 할 일 이름·같은 세션일 때만). 둘 다 없으면 **세션 전체 값을 대신 쓰지 않고** `기록 없음` 입니다.
- 같은 누적값이 두 번 찍힌 이벤트(중복)는 늘어난 양이 0 이라 더해지지 않습니다.
- 누적값이 줄어들면 카운터가 처음부터 다시 센 것으로 보고, 새 누적값을 그대로 더합니다(음수로 빼지 않음).
- 할 일 도중에 세션을 새로 열었다면(세션이 바뀜) 앞 세션의 사용량은 이어 붙이지 않습니다 — 시작값을 찾지 못해 `기록 없음` 이 됩니다.
- 모델은 각 이벤트 직전의 `turn_context.model` 로 정합니다. 구간 안에서 모델이 바뀌면 모델별로 나눠 적습니다.

## 토큰 숫자의 관계 (두 번 세지 않기)

Codex 기록의 숫자는 서로 포함 관계가 있습니다. 2026-10-17 에 이 컴퓨터의 실제 기록으로 확인했습니다 — codex-cli 0.144.1 ~ 0.163.0 의 이벤트 19,500여 개가 모두 아래 관계를 지켰고, 0.133.0 ~ 0.136.0 기록은 대부분 지키지 않았습니다(추론 토큰이 출력 밖에 따로 있음).

| 기록의 이름 | 뜻 | 관계 |
|---|---|---|
| `input_tokens` | 입력 전체 | 캐시 읽기가 **안에 들어 있음** |
| `cached_input_tokens` | 그중 캐시에서 읽은 입력 | `input_tokens` 이하 |
| `output_tokens` | 출력 전체 | 추론 토큰이 **안에 들어 있음** |
| `reasoning_output_tokens` | 그중 추론 | `output_tokens` 이하 |
| `total_tokens` | 전체 | `input_tokens + output_tokens` 와 같음 |

측정 줄의 **"입력"은 캐시 안 된 입력**(`input_tokens − cached_input_tokens`), **"캐시 읽기"는 따로** 적습니다. Claude 판 측정 줄과 같은 뜻이 되도록 맞춘 것이라, 두 도구의 줄이 섞여도 요약에서 같은 칸끼리 더해집니다. 추론 토큰은 출력 안에 이미 들어 있어 따로 더하지 않습니다.

## 비용

비용은 **단가와 토큰의 뜻을 확인한 모델만** 계산합니다.

계산식: `(캐시 안 된 입력 × 입력 단가) + (캐시 읽기 × 캐시 입력 단가) + (출력 × 출력 단가)`, 단가는 100만 토큰당 달러. 캐시 쓰기 토큰(`cache_write_input_tokens`)이 있는데 그 단가를 확인하지 않았으면 그 모델은 계산하지 않습니다.

| 모델 | 입력 | 캐시 입력 | 출력 | 출처 | 확인일 |
|---|---|---|---|---|---|
| (아직 없음) | | | | | |

지금은 확인한 단가가 없어서 Codex 판 측정 줄은 모두 `비용 미산정` 입니다. 구독 요금제로 쓰면 토큰마다 돈이 나가지 않기도 합니다. 단가를 넣을 때는 공식 가격표에서 확인하고, 이 표와 `observe.py` 의 `PRICING` 을 함께 고칩니다. 모르는 모델의 비용은 **0 으로 적지 않습니다** — 0 은 "공짜"로 읽히기 때문입니다.

## 요약 ($aml:status)

`summary` 는 `progress.md` 의 측정 줄을 모두 읽어 작업 수 · 걸린 시간 합 · 토큰(대략) · 알려진 비용 합을 보여 줍니다. 측정 줄의 토큰은 `12.3k` 처럼 반올림된 표기라 합계도 **대략**입니다. 비용을 모르는 작업 수와 측정 없는 작업 수는 따로 셉니다. Claude 판과 Codex 판 줄이 섞여 있어도 됩니다.

## 지원하는 형식

codex-cli **0.144.0 이상**의 세션 기록(`session_meta` · `turn_context` · `event_msg/token_count`)만 읽습니다. 그보다 옛 버전, 버전을 알 수 없는 기록, `session_meta` 가 없는 기록, 구간 안에 위 표의 관계가 맞지 않는 숫자가 하나라도 있는 기록은 추측하지 않고 `기록 없음` 입니다. Langfuse 전송은 Codex 판 첫 버전에 없습니다.
