# 완성 기준 확인 — 독립 확인과 자체 확인

/aml:go 가 할 일을 다 끝낸 뒤, 또는 사용자가 "확인해 줘"라고 할 때 씁니다.

## 무엇을 보나

- `spec.md` 의 "완성 기준" 목록 (그대로, 하나도 빼지 않고)
- `AGENTS.md` 의 "확인하는 법" 명령

항목마다 실제로 실행하거나 화면을 보고, 셋 중 하나로 적습니다.

- **됨** — 무엇을 실행했고 무엇이 보였는지
- **안 됨** — 다시 해 볼 수 있는 짧은 순서와 실제로 보인 것
- **확인 못 함** — 왜 못 했는지(도구 없음, 환경 없음 등)와 사용자가 직접 확인하는 방법

코드를 읽기만 해서는 "됨"이라고 하지 않습니다. 확인하는 동안에는 코드나 테스트를 고치지 않습니다 — 찾은 것은 /aml:go 의 고치기 단계로 돌려보냅니다. 체크박스가 다 채워져 있다는 것만으로는 다 됐다는 증거가 아닙니다.

## 독립 확인 (기본)

이 플러그인에 들어 있는 `verifier` 에이전트(`agents/verifier.agent.md`)를 하위 에이전트로 불러 맡깁니다. Copilot 대화에서 `/env` 를 치면 Custom Agents 칸에 `verifier` 가 보입니다.

도우미에게는 프로젝트 위치, 완성 기준 목록, 확인하는 법 명령, 이번에 만든 것 한 줄만 넘깁니다 — "다 됐다"는 결론은 넘기지 않습니다. 도우미는 파일을 직접 읽고 직접 실행합니다.

실제로 불러서 판정이 돌아왔을 때만 `확인 방식: 독립 확인 (verifier 에이전트)` 라고 적습니다.

## 자체 확인 (도우미를 못 부를 때)

verifier 를 부를 수 없거나(플러그인이 꺼짐, 하위 에이전트 실패 등) 결과가 돌아오지 않으면, 같은 세션에서 만든 사람의 결론을 내려놓고 위 두 가지만 들고 처음부터 다시 실행합니다. 기록에는 `확인 방식: 자체 확인 (<못 부른 이유>)` 이라고 적고, "독립 확인 완료"라고 쓰지 않습니다.

## 고친 뒤

고친 것이 있으면 관련된 확인을 다시 돌립니다. 확인하지 못한 완성 기준은 체크하지 않은 채로 두고, 그래서 무엇이 아직 불확실한지 쉬운 말로 남깁니다.
